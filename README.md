# 星光雕刻工坊 · 立式头像挑战

面向抖音直播的 **1080 × 1920、9:16 纯直播画面**。顶部青色本场 Top 10、立式大头像加工、延伸至画面底边的连续输送带、金色标签和右侧积分板；没有成品托盘或独立特写窗。每件作品独立随机获得 **0–100,000 分（含两端）**，评分与雕刻同步增长，在雕刻结束的同一刻定格；同一件作品不会因重绘、暂停、送礼升级或出料重新抽分。

## 真实直播接入：当前支持什么

**可以接真实抖音直播事件。必要 relay 与 DyHub 源码已纳入本仓库，不再需要原来另外两个项目文件夹。** 首次安装仍需联网下载 Python/npm 依赖；平时运行需要连接抖音和头像 CDN。这不是抖音官方开放接口，实际可用性取决于直播状态、登录会话和平台协议。

| 数据 | 当前行为 |
| --- | --- |
| 入场 `member` | 获取昵称、用户 ID 和事件携带的头像；按后台开关、冷却时间进入打印队列 |
| 弹幕 `comment` | 后台「近期直播事件」显示昵称、头像和弹幕正文；普通弹幕不自动打印 |
| 礼物 `gift` | 显示礼物名称、累计数量；满足规则后优先排队或升级已有任务，开启加工位聚焦光效 |
| 点赞、关注、分享/互动 | 上游有推送时在后台显示，不触发打印；内置 DyHub 默认订阅弹幕、入场、礼物、点赞、关注 |
| 头像 | 使用事件提供的头像 URL，经本地代理读取；缺失或下载失败会明确标成示例头像，不能从无头像的消息恢复真实头像 |

## Windows 首次安装

安装 **Python 3.11+、Node.js 20+（含 npm）**。在本项目文件夹打开 PowerShell：

```powershell
cd D:\star-laser-studio
.\setup.ps1
```

脚本创建本项目的 `.venv`，安装 `requirements.txt`，按锁文件安装 `vendor/dyhub` 的依赖，用 Windows 兼容脚本编译采集器，并生成 `.local/live.env`，其中读写密钥自动随机生成。重复执行不会覆盖已有密钥。无需安装 Chrome 即可使用默认轻量采集模式。

若 `python` 未加入 PATH，可以指定已安装的 Python 可执行文件：

```powershell
.\setup.ps1 -Python 'C:\你的Python安装目录\python.exe'
```

若 PowerShell 阻止脚本运行，可仅为这次启动使用 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`，不必修改机器的长期执行策略。首次安装需要访问 Python/npm 软件源；报错时不要跳过依赖步骤。

## 启动真实直播间

在项目目录执行（数字房间号或完整直播间 URL 均可）：

```powershell
.\start-live.ps1 -RoomId 'https://www.douyin.com/root/live/278339149230'
```

一个终端会管理 **网关 → 内置 DyHub 轻量采集器 → 工作室 → 事件桥接器** 四个进程，全部使用本仓库代码。终端保持开启，按 **Ctrl+C** 关闭这次启动的服务；也可在另一终端执行 `.\start-live.ps1 -Stop`。程序只关闭本次启动的进程树，不自动关闭已有的其他服务。

打开：

- [配置后台](http://127.0.0.1:8082/admin/)：确认中继已连接，查看「近期直播事件」，配置打印规则。
- [纯直播画面](http://127.0.0.1:8082/?live=1)：保持打开，或作为 OBS 浏览器来源，**1080 × 1920**。
- [采集器管理台](http://127.0.0.1:8757/)：查看该房间是否为 `live`，必要时管理自己的登录会话。

后台与显示页用途不同：后台只配置和观察；至少保持一个显示页或 OBS 浏览器源运行，任务才会推进。多个显示页中只有一个负责加工，后台不额外打印。

### 礼物与登录会话

匿名会话可能收到弹幕、入场却收不到礼物。需要接收礼物时，在内置采集器管理台为自己的账号设置有效登录会话；也可以把自己的 Cookie 本地填写到 `.local/live.env` 的 `DYHUB_COOKIE=`，然后重启整条链路。采集器会应用到默认账号。不要将 Cookie 发给别人或写入代码、截图和 Git。已导入的会话存于 `vendor/dyhub/data/`，该目录已被忽略；需要清除时在采集器账号管理中清除。

### 房间、速率与其他配置

后台可配置入场打印、重复入场冷却、队列上限、礼物优先级、礼物最低数量、聚焦光效和加工速率，也可暂停、继续或清空等待队列。礼物不打断当前加工，累计连击按增量处理。新版聚焦仅体现为主加工位光效，保持固定整机镜头。评分为 0–100,000 的娱乐性随机分，与外貌无关。

**切换直播间时**：先 Ctrl+C 停止整条链路，再用新的 `-RoomId` 启动，保证采集器、网关和工作室使用同一个房间。仅在工作室后台修改房间号，不会替你切换采集器。完整启动会保留后台已保存的打印规则，重新同步当前房间、网关地址和访问密钥。排队任务与本场榜单保存在运行内存中，重启会清空。

若端口被旧服务占用，先在原启动终端停止旧服务，或使用另一组端口：

```powershell
.\start-live.ps1 -RoomId 278339149230 -StudioPort 8182 -RelayPort 8102 -CollectorPort 8857
```

这时后台、OBS 和采集管理台分别使用新端口。三个端口必须不同；本地服务仅监听 `127.0.0.1`，默认不需要云服务器或公网开放端口。

## 如何判断真的接通

```powershell
.\start-live.ps1 -Check
```

它检查三个 HTTP 服务、工作室中继状态、采集房间状态、最近事件时间和累计事件数，不打印密钥。自定义端口时在 `-Check` 后加上同样的三个端口参数。

1. 采集器房间为 `live`，工作室中继为「已连接」。
2. 在直播间用另一个观众账号发一条弹幕，后台「近期直播事件」出现相同昵称、头像和文字。
3. 收到入场后，后台出现打印任务；显示页运行后使用观众头像加工。平台并不保证推送每一位观众入场。
4. 测试礼物时检查近期事件是否出现真实 `gift`，再检查优先队列和聚焦光效。后台「模拟赠送礼物」仅验证本地逻辑。

「已连接」只说明连接建立；**后台没有真实事件，就不能声称真实直播接入已验证**。房间未开播、会话失效或平台拒绝连接时，应先处理采集器显示的状态。运行日志位于 `.local/logs/` 的 `collector.log`、`bridge.log`、`relay.log`、`studio.log`。这些日志不会被网页直接提供。

网关使用内存实时广播，断线期间事件不补发，暂不提供跨重启队列恢复。头像未显示时检查后台的「使用观众真实头像 / 示例头像」状态及 `studio.log`。

本次内置版独立启动检查：四个服务可正常启动，网关到工作室的测试弹幕可在后台显示，且没有触发打印。目标房间 `278339149230` 当时返回「直播间已结束或未开播」，因此本次未获得真实弹幕、入场或礼物样本。记录见 `output/bundled-live-verification.json`，不要把其中的本地测试弹幕当作真实观众消息。

## 仅打开工作室预览

```powershell
.\start-studio.ps1
```

该命令只启动工作室，可在后台用模拟入场/礼物验证动画，**不会启动真实采集器**。不要与同端口的 `start-live.ps1` 同时运行。沿用既有远程网关时可在后台填写网关、房间和访问密钥；也保留显式 `-RelayProjectPath` 导入旧项目三项消费者设置的兼容入口，默认运行不依赖它。

## OBS 与离线预览

OBS 的基础画布和输出分辨率均设为 **1080 × 1920**，浏览器源 URL 使用 `http://127.0.0.1:8082/?live=1`，宽度 **1080**、高度 **1920**，帧率可设为 **60 FPS**。端口与启动脚本保持一致，浏览器源适配画布即可。建议 OBS 保持唯一的执行显示页，日常配置打开后台。

纯直播页隐藏按钮、侧栏和页面遮罩，只输出场景。普通浏览器预览按 9:16 居中缩放，右上角齿轮打开离线控制台，Esc 关闭。

不接真实直播时，可在项目目录运行静态服务器：

```powershell
python -m http.server 8080
```

打开 [http://127.0.0.1:8080/](http://127.0.0.1:8080/) 或 [纯直播预览](http://127.0.0.1:8080/?live=1)。静态服务没有后台 API 或真实转发连接。不要直接双击 HTML，项目使用 ES 模块。

离线控制台保留模拟观众、自动模拟、暂停和速度。速度为 1×、1.5×、1.8×、2×、2.5×；8 秒机械周期分别约需 8、5.3、4.4、4、3.2 实际秒，默认 **1.8×，约 4.4 秒 / 件**。切速不重置当前作品。同浏览器标签可通过 BroadcastChannel 同步模拟事件，OBS 与 Chrome 的跨进程同步应使用工作室服务。

## 当前场景与随机积分

当前入口 `photo-scene.js` 导出 `challenge-scene.js` 的场景引擎。新版本使用 `assets/challenge-machine-v1.png` 的无头像、无评分底图，结合 Canvas 2D 实时绘制机械动作、头像材料、激光特效和直播信息。固定正面主镜头覆盖完整工作单元，顶部排行榜不随加工镜头缩放。

已移除左侧原料放置区、取原料和装料动作。材料从加工位开始，机械臂仅在雕刻完成后吸附成品、快速放到皮带并归位；默认速度下成品搬运约 0.7 秒。成品直接接触连续传送带，没有托座或收料盘；头像、金边、阴影和标签跟随同一物料向画面底部移动。

头像在主加工位放大并竖直面向观众，成品直接在连续输送带上倾斜摆放，旁边显示金色积分标签。接触点有白热核心、青色辉光、金属火花与少量烟雾；换行、展示、搬运和暂停时关光，雕刻时同步评分。右侧面板显示真实扫描进度和加工阶段，不虚构清晰度、相似度等 AI 检测数据。

扫描继续采用 **16 趟机械往复 × 每趟 4 条细纹，共 64 条显影细纹**。头像、机械臂、激光和评分共用一个机械时钟。8 秒周期包含夹紧、雕刻与评分、归位、成品展示、抓取成品和连续传送；默认 1.8× 约 4.4 秒每件。没有满盘或换盘等待。

右侧金色板显示同步评分、星级、扫描进度、阶段和累计完成数。积分是 0–100,000 的娱乐性随机数，与头像内容或外貌无关。雕刻开始时从 0 计分，按显影进度递增，雕刻结束的同一刻达到最终值，展示和搬运阶段保持不变；暂停同时冻结雕刻和分数。0 分也是合法结果。

真实接入时由服务端在创建加工任务时分配一次积分；客户端完成回报不会覆盖服务端结果。礼物升级既有任务保留原积分，多显示页、重连或页面重绘也不会重新抽分。离线模式在创建本地物料记录时分配一次，后续取放、传送和连续送出始终保留该结果。

顶部 **本场头像排行榜 Top 10** 仅纳入实际完成作品，按积分从高到低排列，同分保留完成顺序；未完成的排队或加工头像不会提前上榜。空榜显示等待信息，不填充假观众或假分数。直播服务维护本场榜单，不受近期事件列表条数限制；测试预览页中的固定名字和分数只用于可重复的画面检查。

每件物料有唯一编号，夹具、机械臂和输送带保持唯一归属。所有带上成品使用同一皮带步进，最前件连同完整边缘离开画面底部后才归档，不缩小、不淡出、不落入托盘；库存只保留正在显示的物料，连续生产不会积满收料盘。送出后，本场排行榜仍保留已完成作品的积分。

演示头像使用 `assets/portrait-artwork-atlas-v1.png` 高清插画图集，`makeAvatar` 默认生成 768 × 768 圆形画布。真实直播使用观众头像，加载失败则显示明确标注的演示回退。彩色肖像和激光反应属于直播视觉演示，不用于推算实机材料反应、加工能量或精度。
